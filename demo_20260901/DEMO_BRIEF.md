# Shelley’s Poochie Parlour – Stamford Limited | Local Concept Demo Brief

Status: `LOCAL STATIC CONCEPT — NOT DEPLOYED, NOT AUTHORIZED TO SEND`.

## P0 scope

- Audience: a Stamford dog owner deciding whether the parlour feels right for a routine groom, a first groom, or a nervous dog.
- First-screen task: identify the business as dog grooming in Stamford and reach the existing phone/Fresha booking route without ambiguity.
- Core commercial story: specialist care and real groomed-dog imagery, then services, local confidence, and a simple external booking handoff.
- Scope: one responsive static HTML/CSS page; public official logo/gallery images; both official locations, phone/mailto, official-contact-form link and outbound Fresha booking link.
- Non-scope: no payment, booking, form submission, CMS, database, login, copied live availability, review count/text, static Fresha price/duration catalogue, named platform staff, platform portfolio media, invented qualifications or third-party platform embedding.
- Demo status: opening hours remain excluded because the official site/Fresha schedules conflict; the page hands off current Stamford availability to Fresha.

## P1 visual/reference logic

| Reference input | Keep / adjust / reject | Reason |
| --- | --- | --- |
| Official pink/black/white brand cues and dog imagery | Keep, with a darker berry base and acidic pink accent | Retains real business recognition without recreating the dense existing collage. |
| Current homepage collage | Reject as the hero structure | It hides the Stamford proposition and clips at 390px. Use one controlled official dog image in a framed editorial composition instead. |
| Existing Fresha booking | Keep as a single outbound action | It is the real appointment system. The static page must not imitate it. |
| Generic pastel pet-salon aesthetic | Reject | It is a category default and would lose the business’s assertive black/pink identity. |

## P2 page architecture

1. Brand/nav and hero, addressing location and service with one outbound booking action.
2. Service repertoire as an asymmetric image-led grid.
3. Care approach with nervous-dog/private-booking facts.
4. Two-location visit information with a current-availability handoff.
5. Practical FAQ/service boundary and genuine external contact routes.
6. Visual gallery rhythm using distinct official source images.
7. Closing booking/contact split, with the same single booking intent.

## P3 acceptance criteria

- Desktop and 390px are complete, legible, keyboard reachable and show no horizontal scrolling.
- Uses the inventoried official logo plus only ledgered official images; no Fresha image/review material.
- Every factual statement is sourced in `CUSTOMER_PUBLIC_INTELLIGENCE.md`; opening hours remain excluded because the two current public sources conflict.
- Fresha is an external link only for live prices, durations, team, reviews and availability. No copied platform material, tracking, login, deployment or customer contact.
- Client-visible text has no internal/process/rights language, placeholders, TODOs, fake metrics or claims.
